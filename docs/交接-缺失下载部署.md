## 2. 已验证事实（接手人不必重查）

### 2.1 本机一手实测（写在 `common.ps1` 注释里，2026-09-24 记录）

| 事实 | 数据 |
|---|---|
| hf-mirror.com 直连 | 0.04 MB/s，且 huggingface_hub 10 秒读超时假死（`.incomplete` 卡 0 字节） |
| curl.exe 走本机代理 | **3.07 MB/s 稳定**（3 分钟 553 MB 不掉速），差 **75 倍** |
| `Get-HfProxy` 代理探测 | 试 7890 / 7891 / 10809 / 1080；`HF_PROXY=none` 强制直连 |
| `Invoke-HfDownload` 幂等 | 已存在且大小正确的文件跳过，重跑不重下 |
| `Get-RemoteSize` | 先 HEAD；hf-mirror 对非 LFS 小文件偶发 `Content-Length: 0`，此时用 1 字节 Range GET 读 `Content-Range` 总长 |
| 文件清单 | `$HF_ENDPOINT/api/models/{repo}`（默认 HF_ENDPOINT=hf-mirror.com，`HF_ENDPOINT` 可覆盖） |

⇒ **下载统一走 curl.exe，弃 huggingface_hub**。这是拿实测换来的选型，接手人不要改回 hf_hub。

### 2.2 本会话实测（2026-10-26）

- 镜像 API 可用：`https://hf-mirror.com/api/models/{repo}/tree/main?recursive=true`
  返回每个文件的**精确大小 + LFS sha256**（`e.lfs.size` / `e.lfs.checksum`）。
- 关键权重镜像尺寸（已核对）：H3 扩散 **20.97 GB**、文本编码 **15.69 GB**、
  video VAE **2.81 GB**、audio VAE **0.61 GB**、turbo LoRA **1.96 GB**。
- **完整性校验可行**：本机 `minimax_h3_fl2va_pruned_int8_convrot.safetensors` 本地 20.97 GB
  与镜像完全一致。
- 网络抖动形态：偶发 `SSL: UNEXPECTED_EOF_WHILE_READING`，**重试即过**（SeedVR2 的 tree
  请求失败 1 次，重试成功）——写下载逻辑时必须带重试循环。

### 2.3 外部来源

- **curl.exe**：Windows 10 **1803 起随系统内置**（curl.se 官方历史页，一手），
  位于 `C:\Windows\System32\curl.exe`，`-C -` 断点续传。⇒ 启动器零依赖约束下不需要任何第三方下载库。
- **hf-mirror.com 官方**：`HF_ENDPOINT` 环境变量用法、`huggingface-cli download --resume-download`、
  hfd(aria2)；Gated repo 需官网 token —— **本方案涉及的所有仓库都是公开的，不涉及登录**。
- **GitHub 资产直连国内不稳**：`ghproxy.net` / `gh-proxy.com` 镜像前缀可用
  （`github-push-universal` skill 2026-10-26 实测：直连 206 + 正确魔数）。

## 3. 分期任务清单

### P0 · 缺失清单卡 + 一键安装（核心）

- [ ] 新增 **`launcher/部署清单.py`**（纯数据模块，风格对齐 `桥接资源.py`）：
      每项 = `key / 名称 / 判定文件(可多个) / 期望大小 / 对应安装脚本 / 一句话描述`。数据见 §4。
- [ ] `运行时.py` 新增 `deploy_inventory(cfg)`：逐项探测，返回 `(key, 名称, 状态, 缺失说明, 期望大小, 脚本)`。
      判定 = 文件存在 + **大小校验**（能发现"下了一半"：本地 < 期望 → 标"不完整"）。
- [ ] `视频方案启动器.py` 新增**「缺失与部署」卡**（建议放设置区下方或独立导航项）：
      逐项 ✓就绪（灰）/ ✗缺失（红，标"多大"）/ ⚠不完整（琥珀） + 「一键安装」按钮。
- [ ] 点击 = 后台线程 spawn `powershell -ExecutionPolicy Bypass -File <安装脚本>`，
      stdout/stderr **流进现有日志窗**（复用服务面板的子进程日志管道，逐行 `strip_ansi`）。
- [ ] 任务互斥：同一时刻只允许一个安装任务；运行中按钮置灰。
- [ ] 完成回调：重跑 `deploy_inventory` 刷新清单；装了 custom_nodes 时提示
      「需重启 ComfyUI 生效」（服务面板已有重启能力）。
- **验收**：本机点 Video2X「安装」→ 出现 `C:\AI\Video2X\video2x.exe` → 清单变 ✓；
  再点一次 → 秒级返回（幂等跳过）。

### P1 · 单文件补下 + 镜像回退（不想跑整套安装时）

- [ ] `hf_pull(repo, files, dest)`：tree API 拿清单+大小+sha256 → 逐文件
      `curl.exe -L -C - --retry 8 --retry-delay 5 -o <目标>` → 轮询文件大小出进度 → 完成校验。
- [ ] 代理探测移植成 Python（对齐 `Get-HfProxy`：7890/7891/10809/1080，`HF_PROXY=none` 直连）。
- [ ] GitHub 资产（Video2X / ffmpeg zip）直连失败自动切 `https://ghproxy.net/<url>`、
      `https://gh-proxy.com/<url>`。
- [ ] 进度 UI：清单项上显示 `已下 X.X GB / Y.Y GB (Z%)`。
- **验收**：删掉任一权重 → 补下 → 本地大小与 tree API 一致；中断后重试从断点继续（文件大小只增不减）。

### P2 · 体验补全

- [ ] 下载速度显示（两次轮询差分）。
- [ ] SHA256 校验（tree API 的 `lfs.checksum` 就是 sha256）替代/补强大小校验。

## 5. 风险与对策（全部已验证）

| 风险 | 对策（依据） |
|---|---|
| hf-mirror 直连龟速/假死 | 下载前先探代理，探测不到在 UI 上警告"建议开代理"（本机实测差 75 倍） |
| 网络抖动 `SSL UNEXPECTED_EOF` | 所有请求带重试循环（本会话实测重试即过） |
| 改 ps1 踩编码坑 | **P0/P1 不改任何现有 ps1**；新增脚本必须 UTF-8 with BOM（AGENTS 铁律） |
| 大文件下载卡 UI | 全部后台线程，主线程只刷清单；复用现有日志管道 |
| 装完节点不生效 | 完成回调提示"重启 ComfyUI"（服务面板已有重启能力） |
| 磁盘空间不足（H3 五件套 ≈ 41 GB） | 清单标体积；P2 加空间预检 |
| API 路径误推构建产物 | push 一律走 `github-push-universal` 的 git 通道（`--git-only`），不走 Contents API |

# 问题：PowerShell 5.1 把中文脚本读成乱码

**TL;DR**：`.ps1` 存成 UTF-8 **without** BOM，PS 5.1 按 ANSI 解码，每奇数个连续汉字多出半个字节、会吞掉紧随其后的字符——吞引号就语法错误，吞换行则静默合并两行（不报错）。

- 问题：含中文的脚本报语法错误且报错位置对不上；也可能一声不响地把下一行注释掉，脚本照常跑完但少做一步
- 根因：PS 5.1 只看 BOM 判断编码，无 BOM 就退回系统 ANSI 代码页。汉字与中文标点都是 3 字节，而 GBK 按 2 字节一组，奇数个连续非 ASCII 字符就余下半个字节，去和后面的结构字符凑成一个字
- 实测（PS 5.1）：`Write-Output '中'`（3 字节，奇）→ `字符串缺少终止符`，尾引号被吞；`# 中`＋换行（奇）→ **0 错误**，但下一行被并进注释、整句不执行；`# 中文`（6 字节，偶）→ 正常。所以「有时没事」不代表没问题
- 解决：把文件另存为 **UTF-8 with BOM**（写入时先写 `EF BB BF` 三字节）
- 预防：改完 `.ps1` 跑一次 `python tools/check_text.py`（已接入 CI）。kit 托管文件（`schema/kit.lock.json` 的 `files` 键）不在检查范围，其编码归上游 repo-kit，本仓改了会 `KIT LOCK: FAIL`
